## 一、现状诊断（三条，各带行号证据）

### 1.1 卡中卡 —— "臃肿"的结构性来源

| 选择器 | 位置 | 底色 | 边框 | 圆角 |
|---|---|---|---|---|
| `.planner-shell` | `landing.css:13-21` | `--card` `#F6EFDD` | `1px --line` | `--radius-lg` |
| `.form-card` | `landing.css:94-99` | `--card` `#F6EFDD` | `1px --line` | `--radius-lg` |

**两者底色、边框色、圆角完全相同。** 分区卡不是"浮在外壳上的物件"，而是在同一张纸上又描了三个同色的框——眼睛读不出层级，只读出一堆框线。

叠出来的垂直留白也要命：

```
shell padding-top     24px  (--sp-6, landing.css:16)
  card padding-top    20px  (--sp-5, landing.css:95)
  → 第一个字段离单据顶边 44px
card + card 间距      16px  (--sp-4, landing.css:101-103)
```

**卡与卡的距离（16px）小于卡到内容的距离（20px）**——组间呼吸比组内还小，三个分区糊成一坨。这就是"臃肿"的量化来源。

另：`.planner-shell` 在 `landing.css` 里被声明三次（`:13` 尺寸底色 / `:167` 打孔存根内边距 / `:520` 计数器），三件事散在三处；`.preview-band` 被声明两次（`:359` 与 `:544`），后者覆盖前者把色带从 72px 抬到 **108px**。

### 1.2 层级扁平 —— 所有字段一样重

- `.field label`（`controls.css:22-28`）对必填与可选**一视同仁**：全员 `--fs-xs` + `--fw-bold` + `--muted`。唯一区别是必填项多一枚红星。
- 所有控件同为 44px 高（`--control-h`）、同样白底、同样 `1px --line` 描边、同样 `--radius` 圆角（`controls.css:40-60`）。
- 结果：「目的地城市」——整页最关键的一个框——和「住宿连续性」（7 选 1，极少动）视觉权重**完全相同**。用户的眼睛没有任何落点。

「旅行天数」也是个读错的对象：`.readonly-value` 在 `controls.css` 被重定义三次（`:44` / `:58` / `:82`），最终底色从 `--card` 翻成 `--paper`，成了卡上唯一一块"凹下去"的区域——但它**仍然是 44px 高 + 1px 描边**，读起来像第 4 个输入框，而不是一个推导出来的读数。

### 1.3 旅游缺位 —— 所有物料都指向"票据"，没一处指向"旅行"

现有装饰清单：打孔线、锯齿撕边、打孔列、条码、印章、幽灵编号。它们全在讲「这是一张票」，**没有一件在讲「你要出门了」**。

唯一的旅行线索是票头色带上那两行城市名。而：

- **出发城市与目的地城市被拆到两张卡**——目的地在 NO.1（`index.html:50`），出发地在 NO.2（`index.html:92`）。票头色带却把它们并排显示（`index.html:40-42`）。预览说"湛江 → 广州"，表单要上下两处找。
- **幽灵编号压着字段标签**：`.form-card::after`（`landing.css:529-541`）96px 大字 `opacity: 0.05`，定位 `top: var(--sp-2); right: var(--sp-4)`——正是分区卡右上角，也就是第三列表单 label 的位置。截图里那枚「02」正压在「交通方式」上。
- **日期只有数字**：`2026/10/10`。没有星期，读不出"这是周末出发"还是"工作日请假"。

`2026/10/10` → `2026/10/10 周六`。

### 4.3 两城输入框加地理前缀

出发/目的地两个输入框左侧各一枚内联 SVG 定位针。

## 八之三、修复 6 · 邮品与墨线风景（补做，含一次整版重画）

### 第一版为什么被推翻：风格不属于这个页面

第一版画的是**粉彩剪贴画** —— 淡蓝的天、薄荷绿的山、天蓝的海，配白色圆模切底和投影，
三枚圆贴纸散在卡片边缘。

问题不在尺寸或位置，在**它跟这个页面不是一套语言**。这页通篇是"印刷票据"：
牛皮纸底、深墨字、等宽数据、虚线齿孔、打孔列、条码、橡皮章 —— 全部是**扁平单色的墨印在纸上**。
粉彩插画来自一套完全不同的设计系统，贴在牛皮纸上就是外来素材。

**判断标准**：新素材必须只用页面自己的三支色（墨 `#2B2118` / 票据蓝 `#1B4ED8` /
印章红 `#C93A2B`），描线不填充，像铅印上去的。

### 第二版：题材也换成这页天生该有的两件邮品

- **齿孔是这张单据的母题** —— 打孔分隔线、联票券缺口、左缘打孔列全都靠它。
  → 所以**邮票**贴切（齿孔边用 SVG `mask` 真剪出来，不是画上去的）。
- **它本来就有两枚橡皮章**（待出票 / 已出票）。→ 所以**邮戳**贴切。
  邮戳环里那串编号就是抬头上那个 NO.20261008 —— 章是盖在这张单据上的。

### 两条硬教训

**一、SVG 注释里不能出现连续两个减号。** 本轮连踩两次 —— 先在 `sticker-plane.svg` 注释里
写了 CSS 变量名，又在 `scene-travel.svg` 里写了第二个，两处都让整张 SVG 变成非法 XML，
浏览器直接显示碎图。校验方式：

```bash
python -c "import xml.etree.ElementTree as ET, glob; [ET.parse(f) for f in glob.glob('*.svg')]"
```

**探针抓不到这类错误** —— 判据 4 只扫 `.html/.css/.js` 的文本，不看 SVG 能否解析。
碎图会静默上线。

**二、风景带的画幅要大于容器宽度。** 初版 600 宽，在 1180 的容器里 `repeat-x` 铺了两遍，
能看见两个太阳并排。改 1400 宽后（而 `--shell-max` 是 1180）桌面档一屏内不出重复。

## 九、红线

- **不动** `buildTripPayload` / `validateTripPayload` / `syncDateRange` / `getTripDays` 的任何分支与返回值
- **摘要句只读已填值，不编造任何未填数据**——未填项整段省略，禁止出现估算/示例值（沿用 `findMealCost` 的既有规矩）
- `preview-stamp`（待出票）只在着陆页票头出现，与结果页「已出票」不混用
- **emoji 仍为 0**：新增图标必须是内联 SVG，且不得出现在 `static/` 下任何文件的文本内容里（判据扫全目录）
- **渐变白名单仍六项**，不新增
- 动效仍归「出票」四幕单管，本单**零新增动效**
- 类型（必填/可选）分级只加视觉权重，**不新增任何校验规则**——`required` 属性用于选择器匹配，`validateTripPayload` 一行不改
- 修复 2 搬 DOM 时 `id` / `name` 一个不许改
