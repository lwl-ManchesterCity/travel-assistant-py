## 三、A 类 · 会真的看见

### A1 线路色整天错位

**现象.** 同一天的"券左缘色条 / 当天卡片强调色 / 地图折线"三处**不对齐，整体错后一天**：

| | 第 1 天 | 第 2 天 | 第 3 天 | 第 4 天 |
| --- | --- | --- | --- | --- |
| `.day-stub`（券左缘） | 蓝 | 祖母绿 | 琥珀 | 青 |
| 地图折线 `LINE_COLORS[i]` | 蓝 | 祖母绿 | 琥珀 | 青 |
| `.day-section`（当天卡片） | **祖母绿** | **琥珀** | **青** | **蓝** |

**根因.** `app.js:1282` 把 `#day-list` 的 innerHTML 写成 `dayStrip + days.map(...)`，
于是 `<div class="day-strip">` 占了 `#day-list` 的 `:nth-child(1)`，`.day-section` 从 **child 2** 起算。
`result.css:1292` 的 `.day-section:nth-child(4n+1)` 因此永远匹配不到第 1 天。

`.day-stub` 不受影响——它在 `.day-strip` 内部，索引相对的是 strip 的子元素，所以从第 1 天正确起算。
`app.js:1675` 那句注释"和券左缘色条对上"对 `.day-section` 不成立。

**影响面.** `.day-section` 的 `--line-color` 被当天区块消费在很多处，全是错位的：
左边框 `1304`、展开态边框 `1311-1312`、标题色 `1320`、时间轴点 `1386`、地点底 `1422`、
费用牌 `1466/1469`、`1542`、`1797`。不是一处边框色的小事，是整个当天区块的强调色。

**修法（二选一）.**

1. 把选择器的 k 整体减 1：`4n` / `4n+1` / `4n+2` / `4n+3`（最小改动，但读起来反直觉）；
2. 把 `.day-strip` 移出 `#day-list`，另置一个容器（结构上更对，但动 DOM 与 CSS 两处）。

倾向 2：`4n+1` 起算是人读得懂的，错位之所以发生就是因为两类元素被塞进了同一个父节点。

**我怎么验的.** 读 `app.js:1250-1292` 确认 innerHTML 拼接顺序与两类元素的父节点；
grep `result.css` 的 `nth-child(4n` 与 `line-color` 全部消费点；
读 `app.js:1203`、`1677` 确认 `LINE_COLORS` 的索引方式。

### A2 高预算下景点数被砍，备注却写"低预算模式"

**现象.** 日预算 ≥1800 时，`_determine_target_count` 返回 **4**，
但精修环的硬上限 `_determine_hard_budget_attraction_limit`（`planner_agent.py:788-790`）在 ≥450 时**一律返回 3**，
于是第 4 个立刻被 pop 掉，并写上"**低预算模式**已减少景点 X"——明明是最富余的那一档。

**位置.**
- `planner_agent.py:299-300`：`if daily_budget_limit >= 1800: target_count = 4`
- `planner_agent.py:788-790`：`if daily_budget_limit < 450: return 1` / `return 3`
- `planner_agent.py:779`：`notes.append(f"低预算模式已减少景点 {removed.name}")`

**触发条件.** `playable_budget ≥ 1800 × 天数`，即 `(总预算 − 往返大交通) ≥ 1800 × 天数`。
3 天约 5400 元起。**不是够不着的边角**。

**测试覆盖.** **完全没有**——`tests/` 里搜不到 `1800` 这个数，`≥1800` 分支一条用例都没有。

**文档冲突（先拍板再动手）.** `docs/INTERCITY_TRANSPORT_DESIGN.md:79` 写着
「中间天：默认 2 个；可玩日预算 ≥ 1000 给 3 个，≥ 1800 给 4 个」。**代码和文档必有一个是错的**：

- 若**文档算数** → 把 `_determine_hard_budget_attraction_limit` 的上限提到 4，并让备注区分
  "低预算砍的"与"多排不下的"（现在是同一句话，语义完全不同）；
- 若**代码算数**（即最多 3 个是有意的）→ 删掉 `≥1800 → 4` 那一档，同步改文档 4.5 节。

**另注（顺带，不单独列条）.** 文档同处写「< 450 降到 1 个**并写备注**」，但代码在 `<450` 时直接 `return 1`、
不 append 任何 note——只有真的发生裁剪时才写备注。低预算但恰好只排 1 个时，
用户看不到"因预算降为 1 个"的说明。修 A2 时一并处理。

**我怎么验的.** 读 `planner_agent.py:294-307`（`_determine_target_count` 全文）与 `776-790`；
grep `tests/` 确认无 1800 用例；比读 `INTERCITY_TRANSPORT_DESIGN.md:76-81`。

## 四、B 类 · 边角

### B1 城际备注里的"最便宜"可能引用了刚被排除的方案

**现象.** 会出现两条**自相矛盾**的备注并列出现在同一份方案里：

- `intercity_service.py:91-92`：「排除了 N 条到达站不在 X 市内的方案（如『湛江北』），它们更便宜但落地点不对」
- `intercity_service.py:136-137`：「已超出预算的 35%（gate 元），但**最便宜的一档也要 X 元**」

第二句里的 X 正是第一条刚说"更便宜但落地点不对"的那条方案的价格。

**根因.** `_pick_option` 返回 `(chosen, dropped)`，`chosen` 已从候选里剔除掉错城的，
但 `intercity_service.py:90` 传给 `_note_for` 的是**过滤前**的整个 `options`，
`_note_for:132` 的 `cheapest = min(option.round_trip_cost for option in options)` 因此把被排除的算了进去。

**触发条件.** 真实响应里出现过（就是文档第十二节记的那个 873 元 vs 883 元、落在湛江的场景），
日常不一定撞上，但一旦撞上，用户会看到自相矛盾的账。

**修法.** `_note_for` 改成只收留下来的那批（把 `dropped` 剔掉后的列表传进去）。
`_pick_option` 已经把两批都返回了，改动是调用点一行。

**我怎么验的.** 读 `intercity_service.py:85-94`（notes 组装）、`107-138`（`_pick_option` 与 `_note_for`）。

## 五、C 类 · 观感退化

### C1 进度条宽度的过渡是死的

**现象.** 首页等待态"打印小票"的进度条，宽度是**硬跳**而不是平滑增长。

**位置.** `controls.css:576`：`transition: width var(--dur-settle) var(--ease-settle);`
但 `tokens.css` 里只定义了 `--dur-stamp: 0.25s` 与 `--ease-stamp: cubic-bezier(...)`（`tokens.css:130-131`），
**`--dur-settle` 与 `--ease-settle` 从未定义**——全仓库 grep 这两个名字只此一处引用。

**机制.** `var()` 替换失败会让整条声明在**计算值阶段**失效，属性和没写一样，过渡不发生。

**修法.** 补两个 token，或直接改回 `--dur-stamp` / `--ease-stamp`。**先定手感再改**：
900ms 一跳的进度，配 0.25s 的过渡与配 0.6s 的过渡观感不同，这不是纯 bug 修复。

**我怎么验的.** grep 全 `static/` 目录确认只有一处引用、无定义；读 `tokens.css:130-131` 确认现有 token 名。

## 六、D 类 · 撤回（先前说错，留档防重提）

### D1 预算"剩余预算"格的红与进度条/进度状态行的红不一致 —— **触发不到**

- `app.js:1025` 用 `(budget.remainingBudget ?? 0) < 0`
- `app.js:987` / `1032` 用 `budget.remainingBudget ?? (payload.budget - estimatedTotal)`

两处兜底值确实不同，**但这不构成缺陷**：`models/budget.py:17` 是 `remaining_budget: int = 0`，
非 Optional、默认 0，**永远是数字、永远会被序列化**（`planner_agent.py:1048-1062` 逐次赋值），
`??` 的兜底分支根本不会执行。两条路径实际恒等。

**留档理由.** 只差一层没往下核就会把它列成"格子会和状态行反色"。
日后若要给 `remaining_budget` 改成 Optional，这两处必须先统一，否则会真的反色。
