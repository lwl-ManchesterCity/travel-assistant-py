# 景点挑选修订（候选池取前 N / 评分不编 / 中间天上限 3）

状态：**已实施**（2026-10-12，312 passed）。
**本单没做 A1**（线路色整天错位，`DEFECT_REVIEW_20261010.md` 第 1 条）——那是纯 CSS 的活，
和本单这条链不相干，单独修。B1（城际备注引用被排除方案的价格）做在 `intercity_service.py`。
承接：`docs/PLANNER_SELECTION_DESIGN.md`（挑选总设计）、`docs/DEFECT_REVIEW_20261010.md` 第 2 条（A2）。

## 一、要解决的三件事

### 1.1 中间天"谁近谁赢"，分数几乎不起作用

`_fill_route_within` 每轮扫全部候选，比较的 `key` 是二元组：

```python
key = (round(length - 当前动线长度, 6),   # ① 插进来多绕几公里
       rank[id(candidate)])               # ② 分数排名
```

① 优先。**② 只在①精确到小数点后 6 位打平时才说话**——实际几乎用不上。

后果：候选池里有评分 3.2、离起点 1 公里的，和评分 4.7、离起点 3 公里的，
**前者赢**。你设的偏好（`_score_attraction` 里占 +40）和景点评分（0~5）
在中间天这一步基本白设。

**头尾天不受影响**：它们是"半径圈内取分数最高"，分数说了算。

### 1.2 评分本身可能是假的

`clients/amap_attraction._parse_rating` 拿不到高德评分时**返回写死的 4.5**：

```python
return 4.5          # 高德没给评分时编一个
```

这与刚修掉的酒店 `4.3`（`amap_hotel._extract_rating`）**同形**：编出来的数进了决策，
且页面上跟真评分长得一样，分不出来。一批景点全是 4.5 时，1.1 那个"按分数取前 N"
排出来的是半真半假的序。

### 1.3 A2：中间天的"4 个"档从来没生效过，备注还说反了

- `_determine_target_count`：日预算 ≥1800 → **4 个**
- `_determine_hard_budget_attraction_limit`：**无条件返回 3**

于是 4 个被砍回 3 个，备注写「**低预算模式**已减少景点 X」——高预算说成低预算。
`DEFECT_REVIEW_20261010.md` 已认定：那一档无任何用例支撑，文档 4.5 那句更像设想而非结论。

## 二、改动

### 2.1 中间天的贪心池只取「评分前 5、且还没用过的」

- **位置**：`_compose_day_route` 的 `candidates`（进来时已按 `_score_attraction` 降序）。
- **切法**：`[a for a in candidates if self._attraction_key(a) not in used][:5]`。
  顺序不能反——**必须"先滤掉用过的、再取前 5"**，否则玩到第 3 天前 5 可能全被用过，池子空掉、一个都排不出来。
- **不足 5 个就全取，不补**。（高德一页约 10 个，正常够；只有筛选条件极苛刻时才不够。）
- **头尾天不切**：它们本来就只看分数，切了反而可能让半径圈空掉。
- 新常量 `_GREEDY_POOL_SIZE = 5`。

**已知副作用（接受）**：前 5 若都离得远，贪心只能硬选远的 → 动线变长，
更容易撞 25 公里上限（触发放宽到 50）、甚至排不满 target_count。
这是**用"顺路"换"质量"**，是这次改动有意选的。

### 2.2 评分不再编 4.5

- `_parse_rating` 拿不到就返回 `None`。
- **模型与打分都不用动**：`Attraction.rating` 已是 `Optional[float]`，
  `_score_attraction` 里已有 `if attraction.rating is not None`。
- 与酒店那次同理：宁可在页面上显示"暂无"，也不给决策喂编出来的数。

### 2.3 中间天最多 3 个

- `_determine_target_count` **删掉 `≥1800 → 4` 那一档**，阶梯只剩：
  头尾天 1 / 日预算 <450 → 1 / 默认 2 / ≥1000 → 3。
- 删档后 **`_determine_target_count` 的上限（3）与 `_determine_hard_budget_attraction_limit` 的上限（3）合成一套**，
  后者在日预算 ≥450 时**预期变成空转**（进来时已不可能超过 3）。
  **本次不删它**——`_refine_daily_plan` 的调整循环是否会在别处让列表变长，没有逐条验过，
  保留它当安全网比冒险删掉划算。
- **备注文案按真实原因分岔**（现在的写死一句是 A2 的另一半）：
  - 日预算 <450 → 才写"低预算模式已减少景点"
  - 其余情况（安全网真被触发）→ 写清是被上限裁的，**不许再出现"低预算"字样**

## 三、判据（可机器核对）

1. **前 5 生效**：构造 6 个候选、分数严格递减、离起点由近到远（近的那个分最低）。
   断言最终选中的**不含分数最低那个**；且前 5 里"离得最近的"被选中。
2. **先滤后用过的**：构造前 5 全被 `used_attraction_keys` 占掉、第 6 个可用 →
   断言仍然排得出（池子取到第 6 个），**不是空**。
3. **不足 5 个全取**：候选只有 3 个 → 断言不报错、该选谁选谁。
4. **头尾天不受影响**：同样 6 个候选，头尾天仍然只排 1 个、且是**分数最高**的那个。
5. **评分不编**：`_parse_rating({"biz_ext": {}}) is None`、`_parse_rating({}) is None`、
   `_parse_rating({"biz_ext": {"rating": "4.7"}}) == 4.7`；
   且 `_score_attraction` 在 `rating=None` 时不吃 `TypeError`。
6. **A2**：日预算 ≥1800 时最终景点数 **≤3**；且 `notes` 里**不出现"低预算"**。
7. **A2 附**：日预算 <450 且只排 1 个时，备注里**有**"低预算"字样。
8. 全量 `pytest` 仍为 299 passed 起步。

## 四、风险

1. **动线变长**（2.1 的副作用）。撞上 25 公里上限就会放宽到 50，再不行才退回"只给最近的一个"。
   若实测发现中间天普遍排不满，要回头看 5 这个数是不是太小。
2. **评分缺失变多**（2.2）。`_score_attraction` 少了 `+rating` 这一项，
   分数差异会更多落在「偏好匹配 +40」上。这会让"前 5"更像"前 5 个符合偏好的"——
   **方向是对的**，但要承认它改变了排序的含义。
3. **"前 5"这个数是拍的**，没有实测依据。第 5 名和第 6 名分数可能只差 0.1，
   切在哪儿都说得过去；先按 5 跑，看效果再调。

## 五、非目标

- **不动贪心的判据本身**（`key` 仍是"增量里程优先、分数并列裁决"）。
  让分数进入主判据是另一套东西，代价大得多，本单不做。
- 不动头尾天的挑选方式。
- 不动 `_sanitize_attractions`（35 公里聚簇）——它没有实测问题记录，不在本单范围内。
